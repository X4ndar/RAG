# V1.5a design: bring-your-own-model configuration layer

Status: **revision 2, awaiting approval** (corrections from the first review folded in; see "Decisions" near the bottom). Implementation follows the commit plan once the user signs off.

## Goal

Let a tenant configure their own LLM provider through an admin form, store credentials encrypted at rest, verify the configuration works against the live provider, and surface that configuration to the rest of the platform through a single typed factory. No chat UI, no answer agent. V1.5a is the plumbing; V1.5b builds on top of it.

The success criterion is two-fold:

1. A user can POST a config to `/api/v1/admin/llm-config`, click "test connection" in the UI, and see a pass/fail with the actual provider's response.
2. Any backend code path that needs an LLM calls `agent_for_tenant(tenant_id)` and either gets a Pydantic AI `Agent` configured against the tenant's provider, or a typed `LLMNotConfiguredError`. There is exactly one chokepoint where "which model do I call" is decided.

## Scope

**In V1.5a:**

- `tenant_llm_configs` Postgres table, second Alembic migration.
- Application-layer encryption of API keys via `cryptography.fernet.Fernet`, master key from env var.
- Six provider types: Anthropic, OpenAI, Google, Mistral, OpenAI-compatible custom, Ollama.
- Admin API: `POST /api/v1/admin/llm-config` (create or replace), `GET /api/v1/admin/llm-config` (last-4 only), `DELETE /api/v1/admin/llm-config`, `POST /api/v1/admin/llm-config/test`.
- Provider factory `app/llm/factory.py`: `agent_for_tenant(tenant_id) -> Agent`, `build_model(config) -> Model`, `LLMNotConfiguredError`.
- Next.js admin form at `/settings/llm-provider` with conditional fields, masked-key display, "Test connection" button, save-after-pass UX.
- Unit tests for encryption round-trip, provider dispatch, dimension/shape of saved row, missing-master-key error.
- Integration test that POSTs a config, hits `/test` against a mocked provider (Pydantic AI `TestModel`), persists, GETs back the masked view, deletes.
- Updated `LLM_CONFIG_MASTER_KEY` entry in `.env.example`.

**Not V1.5a (explicit non-goals):**

- Chat UI, answer agent, streaming — V1.5b.
- Multiple configs per tenant (per-role: chat vs enrichment vs router) — multi-config lands in V2 when the agent set requires it. V1.5a is one config per tenant, enforced by a UNIQUE index.
- Per-request provider override.
- Cohere and Groq providers (CLAUDE.md mentions them; deferring until a tenant actually asks).
- Master-key rotation tooling (`LLM_CONFIG_MASTER_KEY_FALLBACK`, re-encrypt-on-save loop). Procedure is documented; the helper is a V1.5b commit.
- Usage metering, cost tracking, quota enforcement — out of scope.
- Provider-level rate limit handling beyond pass-through.
- Model parameter overrides (temperature, top_p, max_tokens) on the saved config. Defaults set per-agent at call time.
- Auth roles inside a tenant. V1.5a continues to gate on `X-Tenant-ID` only; "admin vs viewer" arrives with a real auth layer in V2.

## Database schema (second migration)

```sql
CREATE TABLE tenant_llm_configs (
  id                 uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  tenant_id          uuid NOT NULL REFERENCES tenants(id) ON DELETE CASCADE,

  provider           varchar(32) NOT NULL
    CHECK (provider IN (
      'anthropic','openai','google','mistral','openai_compatible','ollama'
    )),
  model_name         text NOT NULL,
  base_url           text,                 -- required for ollama / openai_compatible; optional override otherwise

  api_key_encrypted  bytea,                -- Fernet token; NULL only when provider='ollama' AND no auth required
  api_key_last4      varchar(4) NOT NULL DEFAULT '',

  test_status        varchar(16) NOT NULL DEFAULT 'untested'
    CHECK (test_status IN ('untested','passed','failed')),
  test_error         text,                 -- nullable; populated on test failure for the UI
  tested_at          timestamptz,

  created_at         timestamptz NOT NULL DEFAULT now(),
  updated_at         timestamptz NOT NULL DEFAULT now(),

  CHECK (
    (provider = 'ollama')
    OR (
      api_key_encrypted IS NOT NULL
      AND length(api_key_encrypted) >= 80
      AND length(api_key_last4) = 4
    )
  )
);

CREATE UNIQUE INDEX ix_tenant_llm_configs_tenant ON tenant_llm_configs (tenant_id);
```

**Why these shapes:**

- **`UNIQUE INDEX` on `tenant_id`** enforces one-config-per-tenant in V1.5a. Multi-config goes in V2 by dropping this index and adding a `role` column.
- **`provider` is `VARCHAR(32) + CHECK`**, not a native enum, matching V1's `documents.status` pattern. Adding a new provider in V1.5b is a one-line `CHECK` swap, not an `ALTER TYPE`.
- **`api_key_encrypted` is `bytea`**, not text. Fernet tokens are bytes; `bytea` is the right shape and dodges any text-encoding round-trip surprises.
- **`api_key_last4`** is plaintext on purpose: it's the only thing the UI ever displays in the read path, and storing it separately means we never decrypt the full key just to render the form.
- **`test_status` + `test_error` + `tested_at`** are persisted state, not derived. The admin UI shows "last tested: 2026-05-04 12:34, passed" without a fresh round-trip on every page load.
- **Conditional `CHECK`** at the table level: if provider is anything but `ollama`, both the encrypted blob and the last-4 must be present, and the encrypted blob must be at least 80 bytes. (Fernet's minimum token size is 73 bytes for a 0-byte plaintext; 80 catches truncation bugs while still accepting any real key.) Postgres enforces the invariant; we don't have to.

## Encryption strategy

**Algorithm.** `cryptography.fernet.Fernet`. Symmetric authenticated encryption (AES-128-CBC + HMAC-SHA256), well-vetted, ~10 µs per encrypt/decrypt on a typical CPU. Single dependency we already have indirectly (`cryptography` is a transitive dep of asyncpg via SSL); add an explicit pin to be honest about it.

**Master key.** 32-byte URL-safe base64, exactly the format `Fernet.generate_key()` returns. Stored in the env var `LLM_CONFIG_MASTER_KEY`. Generated once per environment via:

```bash
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

In dev: written into `.env` (gitignored, exists already). In prod: written into the secrets store the deploy uses (Docker secrets, Vault, AWS Secrets Manager). The application has no fallback path — if the env var is missing or malformed, the factory raises `MasterKeyMissing` and every LLM-dependent endpoint returns **503**. The admin config endpoints also return 503: you cannot save a config you cannot encrypt. Better to fail loud than silently store plaintext.

**Per-row vs per-tenant derivation.** V1.5a uses the master key directly. We are not deriving a per-tenant key (HKDF or similar). The honest reason: we only have one master key in V1.5a, derivation adds rotation complexity, and Fernet's authenticated mode already provides integrity per row. If a tenant-isolation requirement ever emerges (e.g., a compliance audit that wants per-tenant cryptographic separation), we re-key on update with HKDF. Documented as a V2 consideration.

**Rotation.** Out of scope for V1.5a's code, but the path is reserved. V1.5b will add `LLM_CONFIG_MASTER_KEY_FALLBACK`: on decrypt, try primary first, then fallback. On any save (or a one-off `scripts/rekey.py`) the row gets re-encrypted under the primary. V1.5a doesn't ship this loop, but the encryption module's public API is just `encrypt(plaintext) -> bytes` and `decrypt(token) -> str`, so adding a fallback later is a single-file change.

**Logging hygiene.** API keys never appear in:

- HTTP response bodies (the read path returns `api_key_last4` only).
- Log lines (the encryption module's `__repr__` masks; the factory logs `tenant_id` and `provider`, never the key).
- Error messages from the test endpoint (we surface the provider's error, but strip `Authorization` headers if they leak in).

A `tests/unit/test_secret_hygiene.py` test asserts the key never appears in the captured logs of a typical save+test flow.

## Provider taxonomy

| Provider key            | Pydantic AI model class | Pydantic AI provider class | Required fields                           | Optional fields  |
|-------------------------|--------------------------|----------------------------|-------------------------------------------|------------------|
| `anthropic`             | `AnthropicModel`         | `AnthropicProvider`        | `api_key`, `model_name`                   | —                |
| `openai`                | `OpenAIChatModel`        | `OpenAIProvider`           | `api_key`, `model_name`                   | `base_url`       |
| `google`                | `GoogleModel`            | `GoogleProvider`           | `api_key`, `model_name`                   | —                |
| `mistral`               | `MistralModel`           | `MistralProvider`          | `api_key`, `model_name`                   | `base_url`       |
| `openai_compatible`     | `OpenAIChatModel`        | `OpenAIProvider`           | `api_key`, `model_name`, `base_url`       | —                |
| `ollama`                | `OllamaModel`            | `OllamaProvider`           | `model_name`, `base_url`                  | `api_key` (rare) |

**Per-provider validation rules** (Pydantic v2 model in `app/models/llm_config.py`):

- `model_name` is required for every provider. We do not maintain an allowlist of model names — provider catalogs change too often and the user knows what their account has access to.
- `base_url` defaults: empty for the SaaS providers, `http://localhost:11434/v1` shown as a placeholder for Ollama.
- `api_key` minimum length 8 chars when provided; pure presence check (the provider will reject malformed keys at test time).
- For `ollama`, `api_key` is optional and accepted as empty string. We then store `api_key_encrypted = NULL` and `api_key_last4 = ''`.

## Admin UI form

Path: `/settings/llm-provider` in the Next.js app. Server component shell that fetches the current config (last-4 view) for the tenant; client component for the form so it can validate and call `/test` interactively.

```
┌────────────────────────────────────────────────────────────────┐
│  LLM provider                                                  │
│                                                                │
│  Provider                                                      │
│  ┌─────────────────────────────────────────────┐              │
│  │ Anthropic                                ▼ │              │
│  └─────────────────────────────────────────────┘              │
│                                                                │
│  Model                                                         │
│  ┌─────────────────────────────────────────────┐              │
│  │ claude-sonnet-4-5                           │              │
│  └─────────────────────────────────────────────┘              │
│                                                                │
│  API key                              ┌──────────────┐        │
│  ┌─────────────────────────────────┐  │ ●●●●●●●●9F4d │        │
│  │ sk-ant-…                        │  │ (last saved) │        │
│  └─────────────────────────────────┘  └──────────────┘        │
│  Leave blank to keep the saved key.                            │
│                                                                │
│  [ Test connection ]      Last test: passed, 2026-05-04 12:34  │
│                                                                │
│  [ Save ] (disabled until a successful test in this session)   │
└────────────────────────────────────────────────────────────────┘
```

**Conditional rendering**, by `provider`:

- `anthropic`, `google`: show **Model**, **API key**.
- `openai`, `mistral`: show **Model**, **API key**, **Base URL** (optional, with placeholder showing the official endpoint as a hint).
- `openai_compatible`: show **Model**, **API key**, **Base URL** (required).
- `ollama`: show **Model**, **Base URL** (required), **API key** (optional). Helper text: "Most Ollama installs don't require a key."

**Validation rules** (client mirrors server):

- Provider must be one of the six.
- Model name: `1..200` chars, no leading/trailing whitespace.
- Base URL when present: must parse as a valid HTTP/HTTPS URL.
- API key when present: `8..512` chars.

**Masking rule.** When a config exists, the form preloads the **non-secret** fields (provider, model, base URL) and shows the masked last-4 (`●●●●●●●●9F4d`) in a read-only chip beside the API key input. The actual input field is empty — the user types a new key only to replace. On submit, an empty API key field means "keep the saved one"; a non-empty value replaces. The server enforces this:

- New row + provider != ollama + empty api_key → 400.
- Existing row + empty api_key → keep the existing `api_key_encrypted`, do not touch `api_key_last4`.
- Any provider + non-empty api_key → encrypt + update both columns.

**Save UX.** The form remembers the last successful test result for the **exact field set in the form**. Editing any field invalidates the test result and disables Save. This is client-side only; the server accepts a save without a passing test (admin override path), but its 201 response includes a `warning` field that the UI surfaces as a yellow banner (see "Save response shape" below). Saving silently when the config might be broken is a support-ticket factory; making the warning explicit pushes the operator to either re-run the test or knowingly accept the risk.

> **TODO (awareness, not a V1.5a fix).** The "exact field set" comparison treats `api_key=""` (empty input field, "keep the saved key" semantics) and `api_key="abc"`-then-deleted as the same form state, but a test result that ran against `api_key="abc"` is _not_ valid for the saved key. V1.5a's save will set `test_status='untested'` whenever the user typed any non-empty key into the field at any point during the session, regardless of what's in the field at submit time, to avoid this trap. Document this in the form code; revisit in V1.5b when we have a session log to lean on.

**Save response shape (201 Created):**

```jsonc
{
  "id": "…uuid…",
  "provider": "anthropic",
  "model_name": "claude-sonnet-4-5",
  "base_url": null,
  "api_key_last4": "9F4d",
  "test_status": "passed",          // | "untested" | "failed"
  "tested_at": "2026-05-04T12:34:56Z",
  "warning": null                   // populated when test_status != "passed"
}
```

When the save bypassed a passing test, `warning` is non-null:

- `test_status=="untested"` → `"warning": "Configuration saved without testing. Run a test before relying on it."`
- `test_status=="failed"` → `"warning": "Configuration saved despite a failed test. The provider rejected the last attempt."`

The UI renders this as an Alert above the form. Banner stays until the next successful test or the next save.

## Test-connection endpoint

`POST /api/v1/admin/llm-config/test` — synchronous, runs the test live each click. Body matches the create payload (so the user can test before persisting). Tests inject an alternate model factory via FastAPI dependency override; production code reads no flags and accepts no env-var swaps. See "Provider factory" below for the `ModelFactory` shape.

**Per-provider timeout.** Cold starts are very provider-dependent. Mistral's hosted endpoint can legitimately take 5–8 s on a cold call; Anthropic and OpenAI are typically <2 s; Ollama on `localhost` should be <1 s. We pick the timeout per provider rather than apply one budget to all:

| Provider             | Timeout |
|----------------------|---------|
| `ollama`             |  5 s    |
| `anthropic`          | 15 s    |
| `openai`             | 15 s    |
| `openai_compatible`  | 15 s    |
| `google`             | 15 s    |
| `mistral`            | 15 s    |

The 5 s on Ollama is a "your local box is unreachable" floor — we fail fast rather than make the user wait. The 15 s on cloud providers is the cold-start budget. Both bake in as named constants in `app/llm/factory.py` so the rationale is in one place.

**Implementation:**

```python
PROVIDER_TIMEOUTS_S: dict[ProviderType, float] = {
    "ollama": 5.0,
    "anthropic": 15.0,
    "openai": 15.0,
    "openai_compatible": 15.0,
    "google": 15.0,
    "mistral": 15.0,
}

async def test_connection(
    payload: LLMConfigCreate,
    tenant_id: CurrentTenant,
    model_factory: Annotated[ModelFactory, Depends(get_model_factory)],
) -> TestResult:
    config = TenantLLMConfig.from_payload(payload)  # plaintext, in-memory only
    model = model_factory(config)
    agent = Agent(model)                             # V1.5a Agent: no system prompt,
                                                     # no retries, returns str (default).
    timeout_s = PROVIDER_TIMEOUTS_S[config.provider]
    started = time.perf_counter()
    try:
        async with asyncio.timeout(timeout_s):
            result = await agent.run("Reply with the single word OK.")
    except TimeoutError:
        return TestResult(
            ok=False,
            error=f"timeout: provider did not respond within {timeout_s:.0f} s",
            latency_ms=int(timeout_s * 1000),
        )
    except (AuthenticationError, PermissionDenied) as exc:
        return TestResult(ok=False, error=f"authentication failed: {exc}", latency_ms=int(_elapsed(started)))
    except (ConnectionError, OSError) as exc:
        return TestResult(ok=False, error=f"unreachable: {exc}", latency_ms=int(_elapsed(started)))
    except Exception as exc:  # noqa: BLE001
        return TestResult(ok=False, error=_safe_provider_message(exc), latency_ms=int(_elapsed(started)))
    return TestResult(ok=bool(result.output and result.output.strip()), error=None, latency_ms=int(_elapsed(started)))
```

`_safe_provider_message` strips any `Authorization:` headers, base64 blobs, or `api_key=` query strings before returning the error to the UI. The full exception is logged at WARN with the API key already masked.

**What the UI sees:**

| Outcome                          | UI display                                                                |
|----------------------------------|---------------------------------------------------------------------------|
| 200 `{ ok: true, latency_ms }`   | Green checkmark, "Test passed (1.2 s)"; Save enabled                      |
| 200 `{ ok: false, error: "..." }`| Red banner with the error text                                            |
| 400 (validation failed)          | Per-field errors                                                          |
| 401 (no `X-Tenant-ID`)           | Same error UX as the rest of the app                                      |
| 503 (master key missing)         | "Service is misconfigured. Contact your operator."                        |

**What persists.** The `/test` endpoint is read-only on the database side. Only `POST /api/v1/admin/llm-config` (the save path) writes `test_status`, `test_error`, `tested_at`. Save-without-prior-test sets `test_status='untested'`.

## Provider factory

Module: `app/llm/factory.py`.

```python
ModelFactory = Callable[["TenantLLMConfig"], Model]


@dataclass(frozen=True)
class TenantLLMConfig:
    provider: ProviderType                  # Literal["anthropic","openai",...]
    model_name: str
    base_url: str | None
    api_key_plaintext: str | None           # decrypted at call time, lifetime is the request


class LLMNotConfiguredError(Exception):
    """Raised when a tenant has no row in tenant_llm_configs."""


class MasterKeyMissing(Exception):
    """Raised when LLM_CONFIG_MASTER_KEY is unset or malformed."""


async def load_tenant_llm_config(tenant_id: UUID) -> TenantLLMConfig | None:
    """Read the row, decrypt the api_key, return a value object. None if no row."""


def build_model(config: TenantLLMConfig) -> Model:
    """Pure-Python dispatch on config.provider. No I/O. Safe to unit test."""
    match config.provider:
        case "anthropic":
            return AnthropicModel(config.model_name,
                                  provider=AnthropicProvider(api_key=config.api_key_plaintext))
        case "openai" | "openai_compatible":
            return OpenAIChatModel(
                config.model_name,
                provider=OpenAIProvider(api_key=config.api_key_plaintext, base_url=config.base_url),
            )
        case "google":
            return GoogleModel(config.model_name,
                               provider=GoogleProvider(api_key=config.api_key_plaintext))
        case "mistral":
            return MistralModel(
                config.model_name,
                provider=MistralProvider(api_key=config.api_key_plaintext, base_url=config.base_url),
            )
        case "ollama":
            return OllamaModel(config.model_name,
                               provider=OllamaProvider(base_url=config.base_url))


def get_model_factory() -> ModelFactory:
    """FastAPI dependency. Returns the production `build_model`. Tests override
    via `app.dependency_overrides[get_model_factory]` to inject a stub that
    returns Pydantic AI's `TestModel`.

    Production code reads NO env-var flag to swap factories. The dependency
    is the only injection point, and it's reachable only through FastAPI's
    DI graph — the worker and any other non-FastAPI code path import
    `build_model` directly.
    """
    return build_model


async def agent_for_tenant(tenant_id: UUID) -> Agent:
    config = await load_tenant_llm_config(tenant_id)
    if config is None:
        raise LLMNotConfiguredError(tenant_id)
    return Agent(build_model(config))
```

**Agent configuration in V1.5a is intentionally minimal:**

- **No system prompt.** The factory returns a bare `Agent(model)`. The test endpoint passes a one-shot user message; future agents (chat, router, enrichment) supply their own system prompts at call time.
- **`output_type` defaults to `str`.** No structured output coercion in V1.5a. The chat agent in V1.5b will set this explicitly.
- **No retries.** `retries=0`. Provider failures surface immediately to the caller; the test endpoint maps them to `{ok: false, error}`. Retry policy is a per-agent decision and lands with the agents in V1.5b.

Stating this explicitly here so V1.5a's implementation doesn't drift toward configuring options it doesn't need yet, and V1.5b knows exactly what it's adding.

**Caching strategy: none in V1.5a.** Configs change rarely, and a process-local cache forces invalidation on key rotation, on save, on tenant deletion. Each `agent_for_tenant` call is one `SELECT … WHERE tenant_id = …` (UNIQUE index, ~0.5 ms) plus a Fernet decrypt (~10 µs). When the chat path lands in V1.5b and we measure latency, we add a TTL cache (60 s, in-process, keyed on `(tenant_id, updated_at)`) only if profiling shows it's worth the invalidation cost.

## Failure modes and HTTP shape

| Situation                                  | Where        | Status | Body                                                                  |
|--------------------------------------------|--------------|--------|-----------------------------------------------------------------------|
| Missing `X-Tenant-ID`                      | Dependency   | 401    | `{detail: "X-Tenant-ID header is required"}` (existing)               |
| Master key env var missing                 | Anywhere     | 503    | `{detail: "LLM service is misconfigured. Contact your operator."}`    |
| Save with invalid payload                  | POST config  | 400    | per-field Pydantic errors                                             |
| Save provider+key combo missing            | POST config  | 400    | `{detail: "api_key is required for provider X"}`                      |
| Save without a passing test                | POST config  | 201    | full saved view + `warning` string for the UI banner                  |
| GET no row                                 | GET config   | 404    | `{detail: "no LLM provider configured"}`                              |
| Test endpoint, provider rejects auth       | POST test    | 200    | `{ok: false, error: "authentication failed: ..."}`                    |
| Test endpoint, provider unreachable        | POST test    | 200    | `{ok: false, error: "unreachable: ..."}`                              |
| Test endpoint, timeout (provider-specific) | POST test    | 200    | `{ok: false, error: "timeout: provider did not respond within {N} s"}` (5 for ollama, 15 for cloud) |
| Test endpoint, provider returns 5xx        | POST test    | 200    | `{ok: false, error: "<sanitised provider message>"}`                  |
| Runtime feature called, no config          | Any agent path | 409  | `{detail: "no LLM provider configured for this tenant"}`              |
| Runtime feature, provider rate-limited     | Any agent path | 429  | `{detail: "<provider message>", retry_after: <provider header>}`     |

The 200-with-`ok:false` shape on the test endpoint is deliberate: a failed connection test isn't an HTTP error, it's an answer to a question. 4xx/5xx on the test endpoint mean the request itself was malformed or the server can't run it.

## Migration plan

One Alembic migration: `0002_tenant_llm_configs.py`. Adds the table, the unique index, the conditional CHECK constraint. No data migration; no existing rows to convert. Existing v1 features (upload, search) keep working unchanged because they don't touch this table.

Migration is generated and applied via `scripts/migrate.sh`, same workflow as V1.

## Testing strategy

**Unit tests:**

- `tests/unit/test_encryption.py` — encrypt → decrypt round-trip; encrypt+decrypt with a different key fails (InvalidToken); empty plaintext round-trip; `MasterKeyMissing` when env var unset.
- `tests/unit/test_factory_dispatch.py` — for each provider, `build_model(config)` returns the expected `Model` subclass with the expected `api_key`/`base_url` propagated. No network.
- `tests/unit/test_llm_config_validation.py` — Pydantic schema accepts well-formed payloads; rejects empty model name, bad URL, missing api_key for non-ollama providers, oversized fields.
- `tests/unit/test_secret_hygiene.py` — captures logs around `agent_for_tenant` and `test_connection`; asserts the API key string never appears in any log line, response body, or exception message rendered for the user.

**Integration tests** (`tests/integration/test_llm_config.py`):

1. POST a valid config for the test tenant → 201, body has `last4` not full key, `warning` is null because `test_status='passed'`.
2. POST `/test` with the same payload, model factory overridden to return Pydantic AI's `TestModel` returning `"OK"` → 200 `{ok: true}`.
3. POST `/test` with a stub model factory that raises `AuthenticationError` on call → 200 `{ok: false, error: "authentication failed: ..."}`.
4. GET the saved config → 200, `api_key_last4` populated, no full key anywhere.
5. POST again with empty `api_key` field → 200, `api_key_encrypted` and `last4` unchanged in the DB (verified by row read in the test).
6. POST without first running `/test` → 201 with `test_status='untested'` AND `warning` populated; the UI is expected to surface it.
7. DELETE → 204; subsequent GET → 404; subsequent `agent_for_tenant` → `LLMNotConfiguredError`.

**Test wiring: dependency injection, not env-var flag.** `get_model_factory` is a FastAPI dependency. Tests override it with `app.dependency_overrides[get_model_factory] = lambda: stub_factory`, where `stub_factory` is a closure that returns a Pydantic AI `TestModel` (or raises a chosen exception). Production code reads no flag and has no swap path; the only injection point is the FastAPI DI graph.

V1.5a integration tests run against an **in-process FastAPI app via `httpx.ASGITransport`**, not against `localhost:8000`, because `app.dependency_overrides` only takes effect on the same process that owns the app instance. The `tenant` fixture still uses real Postgres on `localhost:5432` (or `postgres:5432` when running inside the backend container, via the existing auto-detect in `tests/integration/conftest.py`). This is a different integration-test style from V1's worker-pipeline tests, which had to hit the live container because they exercise an out-of-process worker. V1.5a doesn't touch the worker, so the in-process style is honest and gives us cheap mocking. Document the trade-off in the test module's docstring.

For `agent_for_tenant` (called from non-FastAPI code paths like the future worker), tests `monkeypatch.setattr(app.llm.factory, "build_model", stub)`. Standard pytest, no special hooks.

## Risks

- **Provider SDK churn.** Pydantic AI's provider classes (Anthropic/OpenAI/Mistral/Google/Ollama) are still pre-1.x; class names and arg shapes can shift between minor releases. Mitigation: pin `pydantic-ai` tightly (`>=1.0,<1.1`) and re-pin deliberately in V1.5b. Run integration tests on every dep bump.
- **Fernet master key in `.env`.** Convenient for dev, fragile for prod. We need a real secrets-management story before any paying customer ships. V1.5a documents the migration path (Docker secrets, Vault, AWS SM); V1.5b's rotation tooling makes the swap safe.
- **Test-connection cost.** Hitting the user's provider with a "Reply OK" prompt costs them tokens. Mitigation: keep the prompt and `max_tokens` minimal; document this in the form UI ("This sends a small test prompt to your provider and counts toward your account's usage").
- **Ollama base URL in dev.** Tenants on Docker Desktop will use `http://host.docker.internal:11434/v1`; Linux Docker users need `http://172.17.0.1:11434/v1` or the Docker-network alias. The form's helper text mentions both; the test endpoint surfaces "unreachable" cleanly when the URL is wrong.
